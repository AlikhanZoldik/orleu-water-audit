# Су есебі — проверка журналов водоучёта

## Запуск

В папке проекта выполните `python app.py` (Windows также поддерживает `py app.py`). Нужен Python 3.9 или новее. Браузер откроет http://127.0.0.1:8765. Сервер работает на этом компьютере, включая режим без интернета. Для работы с журналами и симулятором оборудование не требуется. Библиотеки чтения Excel входят в поставку, устанавливать их отдельно не нужно. Если сервер уже запущен, просто откройте адрес. Остановка — Ctrl+C в терминале сервера.

Прогнозы, входные CSV, пороги и раскрытые результаты сохраняются между запусками в `experiments.sqlite3`. При первом запуске после клонирования база пустая. Создайте серию на вкладке «Проверка метода». Номера серий и результаты ниже относятся к локальной демонстрации команды. Для отдельного журнала используйте `python app.py --db jury.sqlite3 --port 8766`.

## Проверка сменного журнала

1. Откройте стартовую вкладку «Проверить журнал». «Попробовать на примере» сразу показывает результат по учебной смене. «Загрузить Excel/CSV» принимает собственный файл для проверки. Журналы обрабатываются в памяти на ноутбуке, без регистрации и внешних сервисов. Результат можно сохранить перед закрытием страницы.
2. Для Excel выберите лист. Первая непустая строка содержит заголовки, далее одна строка соответствует одной смене. Поддерживаются XLSX и CSV в UTF-8 или Windows-1251 с запятой или точкой с запятой. В числах допустима десятичная запятая. Ячейки Excel с формулами должны иметь сохранённые результаты вычислений.
3. Сверьте первые строки с файлом. Выберите период, A, B и C. Если B отсутствует, выберите «Без B · весь канал». Для каждого участка добавьте столбцы хозяйств или отметьте «Отборов не было». Записанный ноль означает измеренный нулевой объём, пустая обязательная ячейка требует уточнения. Названия столбцов менять не нужно.
4. Укажите единицы всего журнала и тип показаний. При наличии отдельного столбца единиц его можно сопоставить для проверки каждой строки. Расчёт принимает только объёмы за общий период. Для мгновенного расхода требуется интегрирование по времени, для накопительных показаний — разность на границах периода. Все результаты выводятся в м³.
5. Выберите для каждого участка столбец допуска по сменам или введите единый допуск на одну смену в единицах файла. Пустой допуск оставляет значимость неопределённой. Допуски симулятора хранятся отдельно. Для канала без B нужен собственный допуск.
6. Нажмите «Проверить баланс». Превышение определяется по модулю остатка. Положительный остаток показывает необъяснённое расхождение. При отрицательном остатке проверьте притоки и границы смены. Нажмите строку таблицы для просмотра столбцов, исходных ячеек, подстановки и причины. «Скачать результаты CSV» выгружает все строки вместе с объяснениями.

Сводка считает уникальные подписанные смены, а превышения и уточнения — по наличию хотя бы одного такого участка. Одна смена может попасть в обе группы. Повторяющиеся периоды помечаются с номерами строк. Запись без периода также требует уточнения.

**Учебный журнал** — [examples/journal.xlsx](examples/journal.xlsx), тот же файл доступен для скачивания на главном экране. В строке 2 исходные остатки равны +10 и +1 м³ при допусках по 2 м³. Измените ячейку E2 с 20 на 30, сохраните и загрузите файл: получите 0 и +1 м³. Если убрать B, получится +1 м³ по каналу целиком. Укажите для A–C свой допуск или оставьте поле пустым.

Для повторения интерфейсных проверок запустите сервер на порту 8765 и выполните `python check_journal_ui.py`. Только для этого теста требуются Chrome и Python-пакет Playwright. Он загружает и скачивает файлы через браузер, проверяет пересчёт, несколько листов и столбцов отбора, случаи неполных данных и экспорт. Исходный учебный файл тест сохраняет без изменений.

## Режим «Проверка метода» — показ жюри за 90 секунд

| Время | Действие проверяющего |
|---|---|
| 0–15 с | Откройте «Проверка метода». Покажите штатный отбор между A и B. Выберите серию 2 или создайте новую симуляцию кнопкой «Зафиксировать пороги». Прочитайте два порога под схемой. |
| 15–35 с | Нажмите «Загрузить слепой прогон». Сценарий случайный. Сверьте показания и самостоятельно посчитайте A − B − отбор и B − C. |
| 35–50 с | Нажмите «Рассчитать и сохранить прогноз». Прочитайте участок и сравните остаток с его порогом. Обновите страницу, чтобы проверить сохранение прогноза. |
| 50–65 с | Нажмите «Раскрыть контроль». Сверьте прогноз с объёмами в двух ёмкостях. На физическом стенде именно теперь проверяющий считывает ёмкости и вводит контроль. |
| 65–80 с | Выберите архивную серию 1 и «Результаты серии». Сравните пропуски, ложные тревоги и локализацию на одних и тех же 30 прогонах. |
| 80–90 с | Во вкладке «Эффект ремонта» введите до ремонта 2 / 1 / 0,3 л и после 1,7 / 1 / 0,3 л. Разница забора при той же доставке и отборе равна 0,3 л. Это иллюстративные значения. |

## Измерения и калибровка

Один CSV содержит один опыт. Формат UTF-8, разделитель — запятая, десятичный знак — точка. Заголовок должен быть таким:

```csv
t_s,stable,A_L,B_L,C_L,take_L
```

Время `t_s` в секундах, шаг ровно 1 с. A, B, C и измеряемый штатный отбор синхронны, все четыре канала в литрах. Нужны объёмы, включая измеренный ноль при закрытом отборе. Два типа входа:

- **Накопительные показания.** В устойчивом окне 11 отсчётов за 10 секунд. Для каждого канала используется конец минус начало. Начальные показания могут быть ненулевыми.
- **Объём за каждую секунду.** В окне 10 строк. Каждая содержит объём за секунду, которая заканчивается в `t_s`. Программа суммирует каждый канал.

После переключения крана оператор или регистратор ставит `stable=0` до установления потока; начало и конец измерения в ёмкостях должны совпадать с устойчивым окном. Датчик фазы в прототипе отсутствует. Начальные переходные строки отбрасываются. Повторное переключение в окне, пропущенная секунда, пустое устойчивое показание или сброс счётчика внутри окна дают отказ от диагноза с причиной. Для повторного опыта запишите новое целое окно.

1. Для физического стенда сначала запишите минимум пять независимых калибровочных прогонов при закрытых сливах и закрытом отборе. В «Новая серия и калибровка» выберите реальные измерения, тип показаний и все калибровочные файлы. Для репетиции доступны восемь модельных CSV в папке `examples/calibration`.
2. Приложение фиксирует три эмпирических порога — максимальный модуль соответствующего остатка по калибровочным прогонам. Участки используют A − B − отбор и B − C, базовое правило использует A − C. В симуляции для калибровки генерируется 16 отдельных прогонов. Порог относится к данному режиму и десятисекундному окну. Новая калибровка создаёт новую серию.
3. Для каждого слепого опыта загрузите отдельный CSV. Контрольные метки и объёмы ёмкостей хранятся отдельно. При физическом опыте проверяющий записывает выбранный сценарий до пуска и вносит его с измеренными объёмами в программу после фиксации. Приложение блокирует повторную запись прогноза и раскрытие без сохранённого прогноза. Журнал рассчитан на независимую проверку через интерфейс, доступ администратора к файлу SQLite остаётся возможным.
4. Тревога возникает при строгом превышении положительного порога. Превышение на обоих участках исключает однозначную локализацию. Большой отрицательный остаток делает участковый вывод неопределённым. Ни один баланс сам по себе не определяет физическую причину.

Для репетиции импорта используйте `examples/run_01.csv`, `run_02.csv`, `run_03.csv` как накопительные показания. Эти файлы синтетические. Открывайте отдельный журнал для такой репетиции, чтобы сохранить физическую серию однородной. Ответы проверяющего лежат в `examples/control.txt`.

## Как читать сравнение

В симуляции перемешиваются 5 нормальных опытов, 5 опытов только с отбором и по 10 сливов на каждом участке. Во время слива штатный отбор тоже открыт. В физическом пилоте используйте такой же заранее перемешанный набор. Записывайте каждый опыт, включая отказы измерений.

Пропуск — слив без тревоги, в том числе при нехватке данных. Ложная тревога — тревога в контрольном опыте. Ошибочная локализация при наличии тревоги уменьшает долю верных локализаций. Её знаменатель включает все истинные сливы. Ошибка объёма — модуль разности между положительной частью остатка на истинном участке и контрольной ёмкостью. Среднее включает все доступные оценки при сливах, даже подпороговые; рядом показано их число. Базовое правило не определяет участок. Для зачёта физической цели требуются полные измерения 20 сливов и 10 контролей, ≥16 верных локализаций и ≤1 ложной тревоги.

В сохранённой модельной серии 1 метод по участкам дал 0 пропусков, 0 ложных тревог и 20/20 верных локализаций. Средняя абсолютная ошибка составила 11,12 мл по 20 оценкам. Правило A − C дало 0 пропусков и 5 ложных тревог. Следующая симуляция использует новый шум и порядок сценариев.

## Проверки и границы опыта

Выполните `python -m unittest -v test_lab`. Тест поднимает отдельный сервер с временной базой, прогоняет все 30 модельных опытов и проверяет импорт трёх CSV, запрет преждевременного раскрытия и перезаписи прогноза, переходные строки, сброс счётчика, эквивалентность двух типов входа и парное сравнение.

На учебных CSV штатный отбор дал остатки +17,244 и −6,263 мл, оба в допуске. Во втором опыте остаток участка 2 составил +313,054 мл при пороге 22,946 мл. В третьем программа обнаружила пропущенную секунду и сохранила отказ от диагноза.

Модель задаёт постоянный расход с небольшими ошибками показаний. Физический пилот должен проверить чувствительность реальных датчиков, устойчивость порогов, полноту сбора в ёмкости и достижение целевых показателей. Экономию проверяют парным опытом с одинаковой доставкой и штатным отбором. Перенос на открытый земляной канал потребует учёта времени добегания, изменения запаса воды и полевой калибровки.
